## 2026-10-26 — Linux study question: why `lsof -i:8080` printed nothing
This was a study question from the Linux course, with no app changes. The user's `lsof -i:8080` printed nothing because the listener is Docker's root-owned `docker-proxy`, and `lsof` run without sudo silently skips other users' processes. The suggested full answer to "kill the program on port 80" was `sudo kill $(lsof -t -i :80)` or `sudo fuser -k 80/tcp`, with `-i :80` rather than `-i: 80`.

## 2026-10-19 — Google / GitHub sign-in
"Continue with Google / GitHub" on the sign-in page. It uses a server-side authorization-code flow (`lib/oauth.mjs`) with the state in a 10-minute `ea_oauth` cookie. A first sign-in creates an account named after the GitHub login or the Google email (made unique), with no password. Later sign-ins match by the provider's user id, never by email. Config lives in `data/oauth.json` or env vars, with a `publicUrl` per provider: Google takes only localhost or a real domain as the callback, GitHub takes a LAN IP. Start redirects to that address first, so the cookies land where the callback does. The OAuth apps themselves are still to be created by the user (steps in the README).
